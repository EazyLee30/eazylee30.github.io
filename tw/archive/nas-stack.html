搭建自動化媒體棧

> 日期: 2026-05-06  |  標籤: homelab, docker, self-hosted, media  |  閱讀時間: ~8 分鐘

我想要一個系統：搜尋任意一部電影，它自動找到資源、下載、重新命名、歸類，然後就能直接看——全程不用手動管理檔案。這篇文章記錄了我如何在一臺 Proxmox VE 家庭伺服器上，用五個 Docker 容器搭建了這套流水線。

◆ 目標

一句話：選一部電影，它就出現在媒體庫裡。

這句話背後是一條由多個服務組成的管線，分別負責索引聚合、種子搜尋、下載、檔案重新命名和媒體播放——全部自動協調執行。

◆ 架構

資料流
使用者 在 Radarr 中搜尋電影
  ↓
Radarr 向 Prowlarr 請求所有索引器的搜尋結果
  ↓
Prowlarr 搜尋 YTS / Knaben / TorrentDownload（Cloudflare 站點透過 FlareSolverr 解鎖）
  ↓
Radarr 選擇最優資源 → 將種子傳送給 qBittorrent
  ↓
qBittorrent 下載到 /mnt/toshiba/Downloads
  ↓
Radarr 重新命名並移動到 /mnt/toshiba/Media/Movies/电影名 (年份)/
  ↓
Jellyfin 檢測到新檔案 → 自動抓取後設資料 → 可以播放了

◆ 服務清單

服務職責埠
Radarr電影管理與自動化7878
Prowlarr索引器管理器（向 Radarr 提供搜尋源）9696
qBittorrent下載客戶端8080
Jellyfin媒體伺服器與串流播放8096
FlareSolverrCloudflare 反向代理8191

◆ 硬體環境

全部執行在一臺搭載 Intel N3450、7.6 GB 記憶體的 Proxmox VE 主機上。PVE 內部的 Debian 13 虛擬機器（VM 102，IP 192.168.123.59）執行所有五個容器。儲存是一塊 1.8 TB 的東芝 USB 行動硬碟，掛載在 /mnt/toshiba，用於存放媒體檔案和下載內容。

◆ 部署過程

1. Docker Compose 配置

所有服務定義在 /opt/arr/docker-compose.yml 中：

services:
  prowlarr:
    image: linuxserver/prowlarr:latest
    container_name: prowlarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/prowlarr:/config
    ports:
      - 9696:9696
    restart: unless-stopped

  radarr:
    image: linuxserver/radarr:latest
    container_name: radarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/radarr:/config
      - /mnt/toshiba/Media/Movies:/movies
      - /mnt/toshiba/Downloads:/downloads
    ports:
      - 7878:7878
    restart: unless-stopped

  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    environment:
      - LOG_LEVEL=info
      - TZ=Asia/Shanghai
    ports:
      - 8191:8191
    restart: unless-stopped

qBittorrent 和 Jellyfin 是之前 CasaOS 安裝的，已經執行中，所以 compose 檔案只包含三個新增服務。

2. 連線 Prowlarr ↔ Radarr

在 Prowlarr 中新增 Radarr 作為應用程式（Settings → Apps → + Add）。填寫 http://<host>:7878 和 Radarr 的 API Key，同步級別設為 Full Sync——這樣在 Prowlarr 裡新增的索引器會自動同步到 Radarr。

3. 新增索引器

Prowlarr 聚合多個種子索引源。我新增了三個無需認證的公開索引器：

  • YTS — 高質量電影資源（720p、1080p、2160p），檔案體積小
  • Knaben — 綜合 BT 元搜尋引擎，聚合多個來源
  • TorrentDownload — 另一個通用公開索引器

Cloudflare 保護的索引器（1337x、EZTV、Kickass）配置了 FlareSolverr，但我的網路路由經過軟路由的 OpenClash 代理，干擾了 Cloudflare 驗證碼的解決。如果你沒有使用透明代理，FlareSolverr 應該能正常解鎖這些站點。

4. 配置 Radarr → qBittorrent

在 Radarr 中新增 qBittorrent 作為下載客戶端（Settings → Download Clients → + Add）。主機地址填伺服器 IP，埠 8080。將分類（Category）設為 radarr，這樣 Radarr 只管理自己新增的下載任務，不會干擾其他種子。

根目錄（Root Folder）設為 /movies（透過 Docker 卷對映對應宿主機的 /mnt/toshiba/Media/Movies）。

5. 配置 Jellyfin

在 Jellyfin 中，電影庫指向 /mnt/toshiba/Media/Movies。當 Radarr 將檔案移動到這個目錄後，Jellyfin 的庫掃描會自動識別，並從 TMDB 抓取後設資料（片名、海報、簡介、字幕）。

◆ 路徑對映——最容易出錯的環節

這套棧最常見的故障原因是路徑不匹配。Radarr 和 qBittorrent 必須對檔案路徑達成一致。因為兩個容器都將 /mnt/toshiba 掛載到相同路徑，所以對映非常直觀： 

宿主机: /mnt/toshiba/Downloads          → qBittorrent 在此保存下载
宿主机: /mnt/toshiba/Media/Movies       → Radarr 将文件移到这里
        /mnt/toshiba/Downloads          → Jellyfin 忽略此目录
        /mnt/toshiba/Media/Movies       → Jellyfin 读取此目录

如果你使用不同的 Docker 卷對映，需要在 Radarr 的 Settings → Download Clients 中配置 Remote Path Mappings。

◆ qBittorrent 認證繞過技巧

qBittorrent 的 Web UI 需要認證登入。為了避免在容器之間傳遞密碼，我在 qBittorrent.conf 中啟用了本地網路認證繞過： 

WebUI\AuthSubnetWhitelistEnabled=true
WebUI\AuthSubnetWhitelist=172.17.0.0/16,192.168.123.0/24

這樣 Docker 容器（172.17.0.x）和區域網客戶端都可以無需密碼連線。如果是公網環境，建議使用正式的認證方式。

◆ 成果

完整流程已跑通：在 Radarr 搜尋 → Prowlarr 在多個索引器中找到種子 → qBittorrent 下載 → 自動重新命名並移動 → Jellyfin 提供播放。整個流程在初始配置完成後完全自動化。

總成本：零（全部開源軟體）。額外硬體：一塊 ¥100 的 USB 行動硬碟。新增一部電影：在 Radarr 中搜尋 10 秒鐘，然後就不用管了。

◆ 後續計劃
