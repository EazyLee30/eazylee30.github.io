搭建自动化媒体栈

> 日期: 2026-05-06  |  标签: homelab, docker, self-hosted, media  |  阅读时间: ~8 分钟

我想要一个系统：搜索任意一部电影，它自动找到资源、下载、重命名、归类，然后就能直接看——全程不用手动管理文件。这篇文章记录了我如何在一台 Proxmox VE 家庭服务器上，用五个 Docker 容器搭建了这套流水线。

◆ 目标

一句话：选一部电影，它就出现在媒体库里。

这句话背后是一条由多个服务组成的管线，分别负责索引聚合、种子搜索、下载、文件重命名和媒体播放——全部自动协调运行。

◆ 架构

数据流
用户 在 Radarr 中搜索电影
  ↓
Radarr 向 Prowlarr 请求所有索引器的搜索结果
  ↓
Prowlarr 搜索 YTS / Knaben / TorrentDownload（Cloudflare 站点通过 FlareSolverr 解锁）
  ↓
Radarr 选择最优资源 → 将种子发送给 qBittorrent
  ↓
qBittorrent 下载到 /mnt/toshiba/Downloads
  ↓
Radarr 重命名并移动到 /mnt/toshiba/Media/Movies/电影名 (年份)/
  ↓
Jellyfin 检测到新文件 → 自动抓取元数据 → 可以播放了

◆ 服务清单

服务职责端口
Radarr电影管理与自动化7878
Prowlarr索引器管理器（向 Radarr 提供搜索源）9696
qBittorrent下载客户端8080
Jellyfin媒体服务器与串流播放8096
FlareSolverrCloudflare 反向代理8191

◆ 硬件环境

全部运行在一台搭载 Intel N3450、7.6 GB 内存的 Proxmox VE 主机上。PVE 内部的 Debian 13 虚拟机（VM 102，IP 192.168.123.59）运行所有五个容器。存储是一块 1.8 TB 的东芝 USB 移动硬盘，挂载在 /mnt/toshiba，用于存放媒体文件和下载内容。

◆ 部署过程

1. Docker Compose 配置

所有服务定义在 /opt/arr/docker-compose.yml 中：

services:
  prowlarr:
    image: linuxserver/prowlarr:latest
    container_name: prowlarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/prowlarr:/config
    ports:
      - 9696:9696
    restart: unless-stopped

  radarr:
    image: linuxserver/radarr:latest
    container_name: radarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/radarr:/config
      - /mnt/toshiba/Media/Movies:/movies
      - /mnt/toshiba/Downloads:/downloads
    ports:
      - 7878:7878
    restart: unless-stopped

  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    environment:
      - LOG_LEVEL=info
      - TZ=Asia/Shanghai
    ports:
      - 8191:8191
    restart: unless-stopped

qBittorrent 和 Jellyfin 是之前 CasaOS 安装的，已经运行中，所以 compose 文件只包含三个新增服务。

2. 连接 Prowlarr ↔ Radarr

在 Prowlarr 中添加 Radarr 作为应用程序（Settings → Apps → + Add）。填写 http://<host>:7878 和 Radarr 的 API Key，同步级别设为 Full Sync——这样在 Prowlarr 里添加的索引器会自动同步到 Radarr。

3. 添加索引器

Prowlarr 聚合多个种子索引源。我添加了三个无需认证的公开索引器：

  • YTS — 高质量电影资源（720p、1080p、2160p），文件体积小
  • Knaben — 综合 BT 元搜索引擎，聚合多个来源
  • TorrentDownload — 另一个通用公开索引器

Cloudflare 保护的索引器（1337x、EZTV、Kickass）配置了 FlareSolverr，但我的网络路由经过软路由的 OpenClash 代理，干扰了 Cloudflare 验证码的解决。如果你没有使用透明代理，FlareSolverr 应该能正常解锁这些站点。

4. 配置 Radarr → qBittorrent

在 Radarr 中添加 qBittorrent 作为下载客户端（Settings → Download Clients → + Add）。主机地址填服务器 IP，端口 8080。将分类（Category）设为 radarr，这样 Radarr 只管理自己添加的下载任务，不会干扰其他种子。

根目录（Root Folder）设为 /movies（通过 Docker 卷映射对应宿主机的 /mnt/toshiba/Media/Movies）。

5. 配置 Jellyfin

在 Jellyfin 中，电影库指向 /mnt/toshiba/Media/Movies。当 Radarr 将文件移动到这个目录后，Jellyfin 的库扫描会自动识别，并从 TMDB 抓取元数据（片名、海报、简介、字幕）。

◆ 路径映射——最容易出错的环节

这套栈最常见的故障原因是路径不匹配。Radarr 和 qBittorrent 必须对文件路径达成一致。因为两个容器都将 /mnt/toshiba 挂载到相同路径，所以映射非常直观： 

宿主机: /mnt/toshiba/Downloads          → qBittorrent 在此保存下载
宿主机: /mnt/toshiba/Media/Movies       → Radarr 将文件移到这里
        /mnt/toshiba/Downloads          → Jellyfin 忽略此目录
        /mnt/toshiba/Media/Movies       → Jellyfin 读取此目录

如果你使用不同的 Docker 卷映射，需要在 Radarr 的 Settings → Download Clients 中配置 Remote Path Mappings。

◆ qBittorrent 认证绕过技巧

qBittorrent 的 Web UI 需要认证登录。为了避免在容器之间传递密码，我在 qBittorrent.conf 中启用了本地网络认证绕过： 

WebUI\AuthSubnetWhitelistEnabled=true
WebUI\AuthSubnetWhitelist=172.17.0.0/16,192.168.123.0/24

这样 Docker 容器（172.17.0.x）和局域网客户端都可以无需密码连接。如果是公网环境，建议使用正式的认证方式。

◆ 成果

完整流程已跑通：在 Radarr 搜索 → Prowlarr 在多个索引器中找到种子 → qBittorrent 下载 → 自动重命名并移动 → Jellyfin 提供播放。整个流程在初始配置完成后完全自动化。

总成本：零（全部开源软件）。额外硬件：一块 ¥100 的 USB 移动硬盘。添加一部电影：在 Radarr 中搜索 10 秒钟，然后就不用管了。
