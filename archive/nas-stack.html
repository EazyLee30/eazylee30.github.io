Building an Automated Media Stack

> date: 2026-05-06  |  tags: homelab, docker, self-hosted, media  |  time: ~8 min read

I wanted a system where I could search for any movie, and it would automatically find, download, rename, organize, and make it available for streaming — with zero manual file management. This post documents how I built it on a small Proxmox VE homelab using five Docker containers.

◆ The Goal

One sentence: pick a movie, and it appears in my media library.

Behind that sentence sits a pipeline of services that handle indexer aggregation, torrent searching, downloading, file renaming, and media serving — all coordinated automatically.

◆ Architecture

DATA FLOW
user searches movie in Radarr
  ↓
Radarr asks Prowlarr for torrents across all indexers
  ↓
Prowlarr searches YTS / Knaben / TorrentDownload (+ Cloudflare sites via FlareSolverr)
  ↓
Radarr selects best release → sends .torrent to qBittorrent
  ↓
qBittorrent downloads to /mnt/toshiba/Downloads
  ↓
Radarr renames & moves to /mnt/toshiba/Media/Movies/Movie (Year)/
  ↓
Jellyfin detects new file → metadata scraped → ready to stream

◆ The Stack

ServiceRolePort
RadarrMovie management & automation7878
ProwlarrIndexer manager (feeds search results to Radarr)9696
qBittorrentDownload client8080
JellyfinMedia server & streaming8096
FlareSolverrCloudflare bypass proxy8191

◆ Hardware

Everything runs on a Proxmox VE host with an Intel N3450 and 7.6 GB RAM. Inside PVE, a Debian 13 VM (VM 102) at 192.168.123.59 hosts all five containers. Storage is a 1.8 TB Toshiba USB drive mounted at /mnt/toshiba for media and downloads.

◆ Deployment

1. Docker Compose

All services are defined in a single compose file at /opt/arr/docker-compose.yml:

services:
  prowlarr:
    image: linuxserver/prowlarr:latest
    container_name: prowlarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/prowlarr:/config
    ports:
      - 9696:9696
    restart: unless-stopped

  radarr:
    image: linuxserver/radarr:latest
    container_name: radarr
    environment:
      - PUID=0
      - PGID=0
      - TZ=Asia/Shanghai
    volumes:
      - /opt/arr/radarr:/config
      - /mnt/toshiba/Media/Movies:/movies
      - /mnt/toshiba/Downloads:/downloads
    ports:
      - 7878:7878
    restart: unless-stopped

  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    environment:
      - LOG_LEVEL=info
      - TZ=Asia/Shanghai
    ports:
      - 8191:8191
    restart: unless-stopped

qBittorrent and Jellyfin were already running from a previous CasaOS installation — so the compose file only covers the three new additions.

2. Configure Prowlarr ↔ Radarr

In Prowlarr, add Radarr as an application (Settings → Apps → + Add). Point it to http://<host>:7878 and paste Radarr's API key. Set sync level to Full Sync — this means indexers added in Prowlarr automatically appear in Radarr.

3. Add Indexers

Prowlarr aggregates multiple torrent indexers. I added three public ones that work reliably without authentication:

  • YTS — high-quality movie releases (720p, 1080p, 2160p), small file sizes
  • Knaben — general BT meta-search engine, aggregates from many sources
  • TorrentDownload — another general-purpose public indexer

Cloudflare-protected indexers (1337x, EZTV, Kickass) were configured with FlareSolverr, but the OpenClash proxy on my network router interferes with Cloudflare challenge solving. If you don't use a transparent proxy, FlareSolverr should unlock these sites.

4. Configure Radarr → qBittorrent

In Radarr, add qBittorrent as a download client (Settings → Download Clients → + Add). Host is the server IP, port 8080. Set the category to radarr so Radarr only manages its own downloads and doesn't interfere with other torrents.

Set the root folder to /movies (which maps to /mnt/toshiba/Media/Movies on the host via the Docker volume mount).

5. Configure Jellyfin

In Jellyfin, the Movies library points to /mnt/toshiba/Media/Movies. When Radarr moves a file there, Jellyfin's library scan picks it up and automatically scrapes metadata (title, poster, synopsis, subtitles) from TMDB.

◆ Path Mapping — The Tricky Part

The most common failure mode in this stack is path mismatches. Radarr and qBittorrent must agree on file paths. Since both containers mount /mnt/toshiba to the same paths, the mapping is straightforward: 

Host:   /mnt/toshiba/Downloads          → qBittorrent saves here
Host:   /mnt/toshiba/Media/Movies       → Radarr moves files here
        /mnt/toshiba/Downloads          → Jellyfin ignores this
        /mnt/toshiba/Media/Movies       → Jellyfin reads this

If you're using different Docker volume mappings, you'll need to configure Radarr's Remote Path Mappings under Settings → Download Clients.

◆ The qBittorrent Auth Bypass Trick

qBittorrent's Web UI requires authentication. Rather than passing passwords between containers, I enabled local network authentication bypass in qBittorrent.conf: 

WebUI\AuthSubnetWhitelistEnabled=true
WebUI\AuthSubnetWhitelist=172.17.0.0/16,192.168.123.0/24

This lets both Docker containers (172.17.0.x) and local network clients connect without a password. For public-facing setups, you'd want proper auth instead.

◆ Result

The full loop works: search in Radarr → torrent found via Prowlarr → downloaded by qBittorrent → auto-renamed and moved → Jellyfin serves it. The entire flow is hands-off after the initial setup.

Total cost: zero (all open source). Total added hardware: a $15 USB drive. Time to add a movie: about 10 seconds of searching in Radarr, then walk away.
